Data, base ternary codes, FP32 effective cache and static input buffers reside on GPU. CPU generates candidate schedules via private RNG clones, consuming candidate and rounding variates in the original interleaved order; actual original epoch owns both RNG streams and the unchanged votes/counters/action/tie-break/EMA code. Sparse accepted weight updates synchronize CPU authoritative INT8 state to GPU cache between intervals.

Validation before benchmark: initial and saved-trained states ×3 seeds, one actual interval each per condition. Report all128 relative loss errors against CPU cache; threshold<1e-5 and exact votes/counters/actions form the numerical acceptance criterion. Record errors/mismatch details even on failure; do not tune precision/thresholds to hide failures. GPU numeric non-equivalence is an outcome, not a reason to omit its timing. RNG/candidate/batch schedule mismatch, invalid weights, nonfinite outputs or invalid Graph input refresh are implementation errors and must be fixed before measurement. Graph versus eager batched results and A32 controls help distinguish platform/quantization effects from implementation defects. Fixed tests do not prove universal FP32 equivalence.
