# 実行確認結果: MNIST / 1,000パラメータ / seed 0

実データによるCPU実験を実施しました。訓練データ10,000件、独立検証1,000件、テスト10,000件です。
3,000蓄積区間、K=16、閾値4、ブロック1座標、同時発火上限1、INT8カウンタを使用しました。

| 指標 | 結果 |
| --- | ---: |
| 検証loss | 2.6540 → 1.1429 |
| 検証accuracy | 8.40% → 75.90% |
| 最終テストloss | 1.1000 |
| 最終テストaccuracy | 78.54% |
| 総発火数 | 567 |
| 訓練forward回数 | 96,000 |
| 訓練forwardの処理例数（候補対の両方を計上） | 12,288,000 |
| 評価・監査込みのforward回数 | 96,119 |
| 学習・評価時間（ダウンロード・前処理を除く） | 約24.8秒 |

実行環境のPyTorchバージョンと全設定は [config.json](config.json)、
集計結果は [summary.json](summary.json)、学習曲線と更新ログは [metrics.csv](metrics.csv) にあります。
実行時の保存先は一時ディレクトリだったため、そのパスがconfigに残っています。
学習済み重みはローカルの `tdt_mnist/runs/verified-1000-seed0/model.pt` にコピー済みです
（生成物なのでGit管理対象外）。

再現用コマンド（`tdt_mnist/` 内で実行）:

```bash
uv run python train.py --seed 0 --steps 3000 --train-size 10000 \
  --val-size 1000 --eval-every 500 --output-dir runs/reproduce-1000-seed0
```

この結果は1回のseedによる、単一座標版での学習動作確認です。
前向き評価だけで学習が進むことは確認できましたが、多座標識別、既存手法への費用優位、大域収束は示していません。
100区間ごとの監査で発火と重なったのは4区間のみなので、summaryの改善率75%を
信頼性の高い更新品質推定と扱うことはできません。詳しい監査には `--oracle-every 1` を使い、監査費も計上してください。
環境が違えば、浮動小数点演算やライブラリの差から完全一致しない場合があります。
