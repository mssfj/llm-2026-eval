# TDT-DによるMNIST学習

`TDT-v4_離散状態遷移学習理論.pdf`の同期型edge evidence方式を試す実験です。
学習対象は最初から最後まで3値重みで、逆伝播・STE・潜在浮動小数点重みは使いません。

## 実行

リポジトリのルートから:

```bash
cd tdt_mnist
uv sync
uv run python train.py
```

既にPyTorchとtorchvisionがある環境では `python train.py` で実行できます。
初回はMNISTを `data/` にダウンロードします。CPUが既定値です。
GPUは `--device cuda` で使用できますが、この規模では同期などの費用が大きいため、まずCPUで試してください。
CUDAで決定的実行に関するcuBLASエラーが出る場合は、起動前に
`export CUBLAS_WORKSPACE_CONFIG=:4096:8` を設定してください。

短い動作確認:

```bash
uv run python train.py --steps 200 --train-size 2000 --val-size 1000 \
  --test-size 1000 --eval-every 50 --output-dir runs/smoke
```

## デフォルトでちょうど1,000パラメータ

28×28画像を固定の平均プーリングで10×10に縮小し、100入力→10クラスの線形分類器へ渡します。
バイアスはなく、**100 × 10 = 1,000個**の3値重みを学習します。隠れ層のないモデルです。
初期ゼロ率は1/3、非ゼロ符号は対称に生成します。

実効重みは `W = αT`。各層の `α = gain / sqrt(fan_in * (1 - zero_rate))` は固定です。
学習パラメータ数はTの要素数で、固定スケールは別に `config.json` に記録します。
3値重みの保存はINT8、活性化・行列積・損失はFP32です。W3/A32による仕組みの検証で、
3値専用演算カーネル、2-bit packing、A3は実装していません。

| 設定 | 形状 | 学習パラメータ数 |
| --- | --- | ---: |
| 既定値 | 100→10 | 1,000 |
| `--pool-size 14` | 196→10 | 1,960 |
| `--pool-size 28` | 784→10 | 7,840 |
| `--hidden-size 16` | 100→16→10、ReLU | 1,760 |
| `--pool-size 28 --hidden-size 32` | 784→32→10、ReLU | 25,408 |

線形モデルは `10 * pool_size²`、隠れ層ありは `(pool_size² + 10) * hidden_size` 個です。
パラメータ数は起動時に表示します。未使用の重みを付け足すことはありません。

## 更新則と実装上の選択

1. ランダムな座標ブロックを選び、K回の測定中は全重みを固定する。
2. 各座標で接続辺を選ぶ。0では `(-1, 0)` / `(0, +1)` を等確率で選び、
   ±1では唯一の接続辺を使う。ランダムな向きφで2候補を構成する。
3. 同一訓練ミニバッチの2回のforwardから `y = loss(T+) - loss(T-)` を得る。
4. `s = -yφ/S` を確率丸めして3値票を生成し、辺ごとの整数カウンタに加える。
5. K回後、外向きの証拠が閾値以上になった辺から最大k座標を更新する。
6. 全証拠を破棄し、次の蓄積区間へ進む。

デフォルトはブロック1座標、K=16、閾値4、k=1です。1座標では多座標相互作用を避けて更新と蓄積を確認できます。
**この設定での成功だけでは、多数の座標を1スカラーで識別できるという中心仮説H2は実証できません。**

発火候補は `外向きのカウンタ値 × S / その辺の測定回数` で順位付けします。
これはヒューリスティックで、真の行動価値として較正済みとは主張しません。同じ座標からは最大1辺を選択します。
途中発火ではなくK回後の判定なので、論文のiid初通過公式をそのままこの実装の誤率として使うことはできません。

Sは区間内で固定し、区間後に `abs(y)` の中央値をEMAで反映します。`--scale-ema 0` で固定できます。
`|s| > 1` はクリップするため不偏性が失われ、その比率を記録します。適応Sはクリップをなくす保証を持ちません。
`--leak < 1` は測定した辺のカウンタに乗算し、ゼロ方向へ整数切り捨てします。
毎区間、発火しない場合も全証拠を破棄するため、陳腐化を避ける一方で測定効率を犠牲にします。
カウンタの区間をまたぐ永続保持、非同期更新、初通過実験、分散プロトコルは未実装です。

## 主な可変パラメータ

`uv run python train.py --help` で全設定を確認できます。

| 引数 | 既定値 | 意味 |
| --- | ---: | --- |
| `--steps` | 5000 | 蓄積区間の数。データセットを何周するかではない |
| `--batch-size` | 128 | 同一候補対で共有する訓練バッチのサイズ |
| `--block-size` | 1 | 1候補対で独立に摂動する座標数 |
| `--measurements` | 16 | 固定状態で蓄積する候補対数K |
| `--threshold` | 4 | 発火に必要な外向きの証拠 |
| `--max-fires` | 1 | 区間あたりの同時更新上限k |
| `--counter-bits` | 8 | 辺カウンタのビット数。8または16 |
| `--scale` / `--scale-ema` | 0.02 / 0.1 | 正規化Sの初期値・区間間の更新率 |
| `--leak` | 1.0 | 測定した辺の証拠を残す割合 |
| `--gain` / `--zero-rate` | 1.0 / 1/3 | 層スケール倍率・初期ゼロ率 |
| `--seed` | 0 | 初期化・分割・訓練乱数 |
| `--train-size` | 0 | 0なら検証分以外の全訓練データ |
| `--val-size` | 5000 | 訓練用60,000件から取り分ける検証数 |
| `--oracle-every` / `--oracle-size` | 100 / 512 | 更新品質の監査間隔・検証件数 |
| `--output-dir` | runs/tdt-1000 | 保存先。既存の非空ディレクトリは上書きしない |

大きな閾値を使う際はKも増やしてください。閾値がKやカウンタ容量を超える設定はエラーになります。
ブロックを大きくすると他座標の影響で票が不確かになり、Sの適切な値も変わります。

比較例（まずブロックサイズだけ変更）:

```bash
uv run python train.py --seed 0 --output-dir runs/block1-seed0
uv run python train.py --seed 0 --block-size 8 --output-dir runs/block8-seed0
uv run python train.py --seed 0 --block-size 32 --output-dir runs/block32-seed0
```

## 結果と判定

- `config.json`: 全引数、正確なパラメータ数、固定スケール、精度、PyTorchバージョン。
- `metrics.csv`: 初期値と全区間のログ。検証損失・精度は `--eval-every` ごと。
- `summary.json`: 初期／最終の検証結果、最終テスト結果、総発火数、計算回数、所要時間。
- `model.pt`: 最終3値重みと設定。推論用チェックポイントで、途中再開機能はない。

`action_accuracy` と `local_regret` は、選択ブロックの各座標のstayを含む全合法行動を
独立検証バッチで比較した値で、発火しなかった座標も含みます。
`fire_delta_loss` は実際に適用する集合更新の損失差で、負なら改善です。
発火なしでは0となり、summaryの `audited_p_improve` と `audited_mean_delta_loss` は
監査した発火あり区間だけを集計します。検証結果は更新の採否や票の生成に使いません。
監査は有限検証標本上の近似で、母集団の真の行動価値ではありません。

訓練のforward回数は `2 × K × steps`。各forwardが処理した例数も記録します。
評価・oracle監査を含む総forward回数／例数を別に記録し、監査費を隠さないようにしています。
これらは実測FLOPs、エネルギー、HBM帯域、同一到達lossでの既存手法との優位性を示す値ではありません。

まず検証損失の低下、精度の上昇、発火数、クリップ率を確認し、seedを変えて再現性を調べてください。
テストセットは最後の1回だけ評価します。高精度を狙う実験は `--hidden-size` を追加して分離してください。
本実装だけでは論文の全Stage A～Fの検証は完了しません。
